## 作った判断(1〜2 回目から引き継ぎ)
- 採用した筋は A「書く → 見る」(STORYLINES.md)。1 人の作業(leads API の入力検証を zod に)を最初から最後まで追い、計器が 1 つずつ点く。B(計器盤の比喩)と C(r だけ)は作っていない。
- cockpit のペインは pane.tsx の行配分と文言をそのまま描いた(空の状態の文言、`▌ルーティング`、`↑0 ↓4`、`l: 最新へ`、トースト、リバート時に Claude へ送る文まで)。作った UI は無い。VS Code は窓を描かず、cockpit が実際に出すトーストだけ。
- 巻き戻しの装置:hook で transcript に「2 additions and 5 removals」が流れた後、reveal で行を消して窓を割り、同じ作業をもう一度、計器付きで見せる。
- 尺は 100 s。当初の見積り(20〜30 s)より長いが、4 つの計器と 2 つの操作を全部見せる「紹介 + 使い方」として 1 本にまとめた。GIF は作らない(本人の指示)。README からは MP4 へのリンクだけ。
- 画面の比率は実物と同じ 55 / 45(ペインは端末の 45% が上限、`PANE_OPEN` は 96 列要求)。端末 127 列 → ペイン 60 列 − 右余白 2 = 58 列。見出しの `app/api/leads/rou…` のような切り詰めも pane.tsx の `fit` と同じ幅で起こしている。
- 履歴の拍:ポインタで ✗ 10:42 の行を押して赤かった時の画面(parse の diff・✗ テスト・ZodError)に戻り、次に Write の行を押して validation.ts の画面に戻る。その間に新しい変更(tests の Edit)が来ても、見えている 3 行は動かず罫に `↑1 ↓1` が出るだけ。
- o の拍:cockpit の実際のトーストに続けて、VS Code(Dark Modern・WSL: Ubuntu のリモート・tests/route.test.ts をハンク先頭の 11 行目で・追加 3 行に緑のガター)の窓が前に出て、約 7 秒見せて引く。VS Code は実物のスクリーンショットではなく、同じ配色と配置で描いたもの。
- 音:Kokoro jf_alpha の日本語ナレーション(speed 1.12)。字幕は日本語 46px + 英語 26px。BGM は Drift – Minimal(PodcastAC, CC BY)を −20 dB、声の下で −55 %。効果音は key(押下)/ pop(印の着地)/ whoosh(窓の分割・確定・履歴の切替・終わり)。
